# 打水（企鹅出水页快捷入口）

单文件静态页 + PWA。两个大按钮，点一下唤起支付宝直接进对应出水口的页面，不用扫码。
统计只存在本机浏览器（localStorage），无后端、无埋点。

## 原理

机器上的二维码是静态的，内容就是 `https://h5.qiekj.com/skip?SN=<设备号>`。
但这个 H5 按 UA 分流：浏览器里只给下载页，**必须在支付宝里打开**才会走到出水页。
所以按钮的实际链接是：

```
alipays://platformapi/startapp?appId=20000067&url=<URL编码后的上面那个地址>
```

`appId=20000067` 是支付宝内置浏览器容器。页面加载时按 UA 判断：
在支付宝内就直接用 https 地址，在外部浏览器就用 alipays:// 唤起支付宝。

## 部署

- 托管：GitHub Pages，分支 `main`，目录 `/(root)`
- 线上：`https://bjbjshao.github.io/water/`
- 更新：改完 `index.html` 后提交推送，Pages 自动重建，30–90 秒生效
- 验证：

```bash
python3 -c "import urllib.request as u,time;print(u.urlopen('https://bjbjshao.github.io/water/?v='+str(int(time.time())),timeout=15).status)"
```

## 加到桌面（安卓）

Chrome 打开页面 → ⋮ →「安装应用」。得到无地址栏的独立窗口。
**改过 manifest 之后要删掉旧图标重装**，否则还是网页快捷方式。

## 功能

- 冷水 / 热水 两个大按钮，深链唤起支付宝
- 出水统计：点按钮自动记一条（时间 + 出水口 + SN），底部显示「上次」，右下「统计」看本月/近 7 天/冷热次数和最近 10 条，可导出 CSV、可清空
- 上限 2000 条自动滚动，不会撑爆 localStorage
- 不做用量估算——每次接多少没法知道，估出来的数字只会误导

## 故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 点了跳到下载胖乖生活 | 页面在浏览器里跑，没进支付宝 | 正常流程应该唤起支付宝；确认按钮下划线是 `alipays://` 开头 |
| 点了完全没反应 | 浏览器缓存了旧版页面 | 加 `?v=数字` 强刷，或清站点缓存 |
| 停在支付宝首页 | 深链被系统拦了一次 | 返回页面再点一次 |
| 统计数字不对 | 它统计的是「点按钮次数」，不是实际出水量 | 正常，取消不计费的也算一次 |

## 边界

- `alipays://platformapi/startapp?appId=20000067` 不是支付宝官方承诺的接口，
  支付宝或企鹅改版可能失效。兜底方案：支付宝「扫一扫 → 相册」选机器二维码截图。
- 不做「自动点立即使用」之类的自动化——那是绕过计费，涉嫌违法。
- 不把付款码、免密授权页放上网页。
- SN 印在机器上本来就是公开的，混淆它没有意义；介意就删仓库。
